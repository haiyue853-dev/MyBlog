# My little world · 我的个人小屋

草莓奶油色的个人空间：公开生活碎片与喜欢的收藏，登录后的私人资料柜，以及 Iris 助手。访客只需昵称即可留言，无需注册账号；无示例个人记录。

## 本地运行

需要 Node.js >=22.16（推荐 Node 24 LTS）。

```powershell
cd D:\MyBlog
npm install
npm run setup-owner
npm run dev
```

打开 http://127.0.0.1:3000 。初始化命令会在本地询问密码，不把密码写到配置或日志里；已有账号可以重设密码并撤销所有会话。点击右上角锁图标登录。

本地预览正式构建：先执行 `npm run build`，再执行 `npm run start`。初始化账号后刷新网页即可登录。

登录后可新增/编辑/删除生活和收藏；新建日常、文章与观后感默认公开，收藏默认仅自己可见；“布置小屋”可以设置名称、介绍、主题色和头像。记录配图会随公开记录一起公开，头像保存后公开。普通上传文件不自动公开。取消记录公开会同时取消对应图片的公开访问；已被访客保存的图片无法收回。

生活和收藏的单条编辑窗口不会因点击外侧而关闭。未保存的文字、设置和已上传照片自动暂存于当前浏览器标签页，重新打开同一条记录可恢复；主动关闭时可继续编辑、放弃修改或保留草稿并关闭。保存成功或放弃修改后清除草稿，关闭整个标签页后不保证保留。批量上传窗口也禁止点击外侧关闭，但尚未上传的本地文件不属于草稿。

单条编辑的正文工具栏支持选中文字加粗、斜体，以及正文／小标题／中标题／大标题选择；标题格式应用到当前行或选中的多行。可切换预览查看保存后的排版，Ctrl / ⌘ + B、I 也可设置加粗与斜体。工具栏还支持圆点列表、编号列表和引用，选中多行可统一设置；列表中 Enter 继续下一项，空白项再按 Enter 退出。文章标题使用圆角标题块、粉色竖线和圆点分级，列表与引用沿用奶油粉主题。排版内容与文字一起保存和暂存草稿，原有 Markdown 记录继续正常显示。

文章和观后感的编辑窗口加宽至最多 1060px、占屏幕高度约 92%，正文输入区加高；手机接近全屏。小屋工具使用收纳箱图标。字号使用主题菜单。工具栏的“插入代码块”可选择语言、粘贴代码，插入后以等宽字体卡片显示并保留缩进；普通段落行首空格按文字缩进显示，显式围栏代码仍保持代码格式。编辑未保存时点叉号或按 Escape，会在中央弹出继续编辑／放弃修改／保留草稿并关闭的确认，滚动位置不影响提示可见性。

文章与观后感的封面支持拖动取景、100%–300% 缩放、重置和桌面／手机预览。在“文章封面”独立选择封面图片，再在“封面取景”里调整；可用方向键微调，缩放滑杆和加减按钮适配手机。取景参数跟文章、草稿和备份保存，换封面会重置，不改动原图；旧文章保留原先偏上／居中／偏下的位置。首页、生活碎片和文章地图使用紧凑的文字卡片；封面在文章内展示，阅读页与分享图使用保存的焦点和缩放，不同屏幕比例会自适应裁切。勾选“提示含剧透”后，卡片、文章地图、时光轴和搜索结果在点击前就显示“含剧透”。首页与生活碎片的文章卡片按参考网站字号设置：桌面标题 27.2px、摘要 16px、日期及阅读信息 14px；手机标题 24px、摘要 16px、日期及阅读信息 13px。

正文输入框按 Tab，或点工具栏的“空两格”，在光标位置插入两个中文全角空格，保持段落缩进且不会被识别成 Markdown 代码块。手动空格、加粗标题下一行及换行的缩进同样在预览和阅读中保留；列表、引用和显式代码按各自格式显示。选中的文字会保留；显式围栏代码内插入两个普通空格。Shift + Tab 仍可切换焦点。缩进随正文和草稿保存。

文章与观后感支持正文插图：将光标放到需要配图的位置，点击工具栏“插入正文图片”，直接从电脑／相册选图上传，也可复用已选图片，填写可选说明及普通宽度／通栏展示后插入。无需提前到照片区上传。封面独立选择或移除，仅插入正文图片时不会自动设置封面。每篇最多 12 张附件；“整理已选图片”可移除、排序或选择已有照片为封面。上传期间不能保存或关闭编辑器，失败保留正文和弹窗，可重新选择。预览和阅读页均可点击图片放大，手机自动适配；底部图库仅展示未插入正文的额外照片。插图随正文保存、暂存草稿和备份，沿用文章照片的可见范围。

公开已发布的文章与观后感底部提供“分享”小浮层，可复制链接、预览并下载 1080×1440 PNG 分享图。分享图包含封面（无封面使用主题底图）、标题、摘要、日期、阅读信息与二维码，链接使用当前访问域名；本地／内网链接会提示上线后重新生成。复制失败时可手动选中链接复制。私密、草稿与回收站内容不能生成，文章更新后须重新生成再下载。

主页“最近更新”展示最新文章的标题与短摘要；“最近的小事”用独立小列表展示日常，点击仍打开照片与心情窗口。编辑器提供“日常记录”“文章”“观后感”三个独立选项；生活碎片点击“写文章”进入文章模式，可设置分类（日常、工作、旅游、观后感或自定义）、专题系列、标签、摘要、封面引导文字与画面位置、剧透提示、最多六项作品资料和一句摘录。封面从照片中选择，未插入正文的额外照片在文章末尾展示。文章打开 `/posts/[id]` 独立阅读页，带字数／阅读时间与上一篇／下一篇，同专题只在该专题内翻读。

旅行地图已按用户要求撤下导航和页面展示，原 `/?view=travel` 显示主页。组件、地图样式、地理数据、地点接口和 `settings.travel` 足迹保留，完整备份及 Cloudflare 迁移仍包含地点。以后恢复时重新接入 `TravelMap`、`travel-map.css`、导航和 Node／Cloudflare 页面路由白名单即可。地图数据来源与投影说明见 [旅行地图数据](docs/travel-map-data.md)。

## 视频作品

视频作品栏目已按用户要求撤下，导航、上传界面和搜索视频分类均不展示，旧 `/?view=videos` 显示主页。视频组件、样式、资料存储与附件权限代码保留，已有内容仍可备份和在回收站恢复；本轮不删除已存文件。

取消视频专用的大文件上传限制，所有上传恢复为每文件 20 MB，Next 请求体配置恢复为 25 MB，Caddy 为 22 MB。保留的视频编辑器中仍有原 100 MB 提示，但组件没有接入网站；未来重新启用时须同步恢复路由、导航、搜索、样式与上传配置。

顶部导航的“文章地图”和“时光轴”分别切换到 `/?view=posts` 与 `/?view=timeline`，保持头部不变，只切换下方内容；地图分类、专题、标签原位筛选，时间轴按上海时区的年月整理文章和日常。原 `/posts` 与 `/timeline` 地址仍可直接访问。公开访客只看到公开内容，私密文章及导航只对站主可见。新增日常与新增文章分别暂存草稿；切换记录方式保留未提交的文章配置。独立阅读页与地图／时光轴适用于本地及阿里云 Node 部署；旧 Cloudflare 静态界面使用原详情窗口读取已有文章。

跳转和翻页箭头统一主题粉色，鼠标悬停或键盘聚焦时渐显并轻移，入口有对应悬停状态；触屏、窄屏和关闭动效时直接显示，下拉菜单箭头保留旋转提示。

文章阅读也使用同一套小屋头部；进入文章、前后翻篇和返回栏目只切换下方内容，导航、小屋工具、登录与动效入口保持一致。直接打开或刷新 `/posts/[id]`、`/posts`、`/timeline` 同样使用完整头部，浏览器返回按地址恢复内容。

文章正文的三级标题会自动生成“本文目录”：电脑在正文右侧跟随阅读显示，手机默认折叠。点击章节定位并随滚动高亮，标题不会被顶部导航挡住；目录项旁可复制章节链接，直接访问、刷新与浏览器返回支持章节定位。代码框与普通文字不进入目录，没有分级标题的短文不展示空目录。

头部搜索图标展开居中的小搜索框，当前页面和地址保持不变。输入后搜索文章、观后感、日常和收藏的标题、正文、分类及标签，支持类型筛选、关键词高亮与短摘要；结果分批展开并在框内滚动。文章进入阅读页，日常及收藏打开原详情；关闭重开保留当前会话的搜索词。访客仅搜索公开已发布内容，站主可搜索私密和草稿。输入框只保留一个叉，点击外部或 Escape 可收起，点击分类不改变框的底色。

访客只在文章底部首次留言时填写昵称，浏览页面无需署名。公开文章与观后感支持评论，提交后直接显示；昵称由当前浏览器身份记住，可在评论区修改，旧留言保留发表时的署名。只需昵称，不需要密码或邮箱。留言本人可删除自己的评论，站主登录后可删除任何评论并以“站主”标记留言；同名昵称不会获得站主身份。昵称最多 24 字、留言最多 2000 字，每页 20 条，访客每分钟最多发表 5 条。评论按普通文字展示，存入数据库并随完整备份保存；撤回公开或改为草稿后，评论仅站主可见。收藏与日常弹窗不增加评论区。

登录后从“小屋工具 → 回收站”找回移走的日常、文章、观后感和收藏。普通删除和收藏批量删除先移入回收站，恢复保留原时间、照片、标签、公开范围、草稿状态、留言、回复与点赞。回收站仅站主可见，照片不会被未使用图片清理误删；彻底删除需确认，移除记录及关联留言、点赞，照片原件留在资料柜。完整备份与 Cloudflare 迁移包含回收站。

登录后从“小屋工具 → 内容管理”整理日常、文章和观后感，可按标题／分类、创建日期、可见范围和发布状态筛选，继续编辑、调整分类、发布或撤回草稿，并将已发布文章设为首页置顶。观后感的类型与电影、韩剧等分类分开保存。编辑器的“保存草稿”存入数据库，可刷新后或换设备继续；“保留草稿并关闭”仍是当前标签页的临时暂存。草稿的文字、配图、点赞与统计仅站主可访问；发布后遵循所选公开范围。

内容管理中的“留言”标签集中显示文章与观后感的评论，提供全部／未读筛选、分页、刷新和已读／未读标记。新访客留言默认未读，站主留言不计入未读；查看原留言会自动标记已读，并在保留头部的文章页定位对应评论，较早的评论同样可以定位，刷新链接仍有效。返回管理页保留留言标签。删除前需要确认；已读状态仅站主可管理，随数据库备份保存，并包含在 Cloudflare 迁移包中。

站主可在管理列表或文章评论区直接回复，每条留言配一段回复，显示在原留言下面并带站主标识。回复最多 2000 字，以普通文字展示；可编辑、确认删除，编辑保留首次署名和发表时间。保存回复会将原留言标记已读，取消未保存的修改会弹出确认框，保存失败保留输入。回复继承文章的可见范围，随完整备份与迁移保存；删除原留言也会清除关联回复。

头部的内容管理、资料柜、Iris 和小屋统计统一收进“小屋工具”，鼠标移入自动展开、移出稍后收起，箭头平滑旋转；手机与键盘保留点击操作，切换后保留头部。管理筛选与行内可见范围使用奶油色圆角菜单、粉色选中状态，支持方向键、Enter 和 Escape。

生活碎片支持多图日记：点击“记一笔”，一次选择最多 12 张照片，可继续添加、设为封面、拖动排序或用箭头前后移动。封面选择不改变照片顺序。上传完成后保存；默认仅自己可见，公开时整组照片随日记公开。详情里可用箭头、缩略图、键盘左右键或手机横向滑动切换，点击照片可查看原图。旧单图日记继续兼容，收藏馆仍使用单张配图。移除照片或取消编辑不会删除资料柜原件，可在资料柜清理未使用图片。

收藏馆点击“批量上传”，一次选择最多 12 张照片，每张生成一张独立卡片；可分别修改标题，统一指定人物／分组、标签和公开／私密。人物／分组会显示在卡片角标上，也用于顶部筛选，可自由输入或选择已有 Jisoo 等名称；从某个分组上传时默认沿用该名称。失败后只重试未完成的文件，已上传原件可复用；保存响应丢失后重试也使用同一记录编号，避免重复卡片。

收藏馆增加“影视片单／小卡收藏”两个页签，首次打开显示影视片单。影视片单参考追番海报墙，支持韩剧、电影、国产电视剧、动漫和其他类型；站主手动填写片名、上传海报、观看状态（想看／在看／已看／搁置／弃剧）、可选评分与年份、总集数与观看进度，以及关联已有观后感。选择“已看”时无需填写集数，卡片和详情不展示观看进度；“在看”等状态仍可记录集数。收藏馆简介仅站主登录后可见，访客列表、详情和搜索均不提供简介；备份保留原文。新影视默认公开，可改为仅自己；未评分不计入平均分。按类型、状态和关键词筛选，每页 18 部；电脑四列、手机两列，进入观后感保留共同头部。小卡原图比例、人物分组、批量上传与管理保留。新增片单信息随草稿、回收站、完整备份及 Cloudflare 迁移保存；不可见或已移除的观后感不会显示给访客。

进入收藏馆时，小卡按短暂错开的顺序渐显；关闭动效时直接显示，卡片的原有悬停与点击不受影响。

内容标签与人物／分组分别设置，提供“小卡、电影、韩剧、国产电视剧”快捷选项，也可以填写自定义标签。收藏馆顶部可以同时按人物和内容标签筛选，例如“Jisoo + 小卡”；搜索也可叠加使用。

点击“批量管理”进入勾选模式，可全选本页或跨页选择，统一修改人物／分组、内容标签、可见范围或删除。批量设置内容标签会替换所选收藏的标签，人物名称保持不变。删除弹窗列出所选收藏，确认后只删除记录，图片原件保留。部分操作失败时保留失败项选择，方便重试。

在“布置小屋”中点击头像选择照片，在圆形预览里拖动调整位置、用滑块缩放（100%–400%），也可用方向键移动。点击“使用这张头像”上传 512×512 裁剪图，再点击“保存布置”生效；取消调整不会上传。GIF 会转为静态头像。

右上角花朵按钮控制唱片、鼠标音符等动效，选择会在当前浏览器记住。第一次访问时遵循系统“减少动态效果”偏好；点击“开启动效”后可单独开启网站动效。更新代码后普通浏览器仍看到旧页面时，按 `Ctrl + F5` 刷新。顶部导航下滑后会合成一条半透明栏，回到顶部恢复分块。每次切换栏目，栏目头、侧栏、正文和页脚依次从透明轻轻浮现，约 0.8 秒完成；关闭动效时立即显示。

## Iris

站主登录后打开 Iris，展开“让 Iris 帮我写博客”：选择文章或日常，输入整理要求，可添加 PNG／JPG／WebP 图片和 PDF／TXT／Markdown／Word（docx）／Excel（xls、xlsx）文档，每次最多 10 份、单份最多 20 MB。点击“整理成预览”后检查文字和配图，再点“编辑并确认发布”；可以修改内容、选择公开或仅自己，也可保存为博客草稿。

生成预览不会创建博客记录或公开图片。只有在编辑器里确认发布才会写入；文档留在私人资料柜，不成为公开附件。当前标签页会保留输入、素材选择、候选预览与编辑草稿，关闭标签页后不保证恢复，长期保存请使用“保存草稿”。失败时可修改后重试，稳定请求编号避免重复创建。新增功能全部位于博客项目，只调用 Iris 已有会话、附件和聊天接口，不需要修改 Iris 源码。

Iris 仅供站主本人使用：先通过右上角锁图标登录现有站主账号，再从“小屋工具”打开 Iris。访客菜单隐藏 Iris；未登录直接访问 `/?view=iris` 显示主页，所有 `/api/iris/*` 接口（含会话、聊天、知识库、原文下载和资料导入）均要求有效站主会话。退出登录后会话立即失效。Node 与 Cloudflare 均先检查登录，再连接或报告 Iris 服务状态。

连接当前电脑的 `D:\agent\Iris-agent`：先按 Iris 自己的启动方式启动 API（默认端口 8000）。本网站不自动启动或修改 Iris。

上述权限控制覆盖博客入口。Iris 独立服务的 8000 端口必须留在受控内网，本机使用时仅监听回环地址；直接公开独立服务会绕过博客登录。部署的内网入口如果要求令牌，将令牌填入服务器端 `IRIS_API_TOKEN`，不要放进浏览器代码。

如需调整配置，复制 `.env.example` 为 `.env.local`。网页、脚本均使用同一个 `DATA_DIR`；默认是项目的 `data/`。

```dotenv
APP_URL=http://127.0.0.1:3000
DATA_DIR=./data
IRIS_BASE_URL=http://127.0.0.1:8000
IRIS_API_TOKEN=
```

Iris 支持会话、NDJSON 流式回答、知识库选择和原文下载。资料柜的文件与 Iris 索引是独立的数据：点击文件旁的箭头，选择知识库并确认，才会向 Iris 导入副本。删除资料柜原件不会删除 Iris 副本。Iris 离线不影响资料柜。对话工具限制在 safe / knowledge 集合，复杂的权限确认请用 Iris 原界面。

## Docker 云部署（Linux 方案）

提供单实例 Docker Compose + Caddy。需要 Linux 云服务器、Docker Compose、已解析到服务器的域名，以及 80/443 端口。首次上线前在本地完成站主账号初始化，防止云上出现可被他人抢注的初始化入口。

当前计划先只部署小屋，Iris 后续再接。配置、成本比较与上线验收见 [安全与部署建议](docs/安全与部署建议.md)。

1. 在本地初始化站主，把项目和 `data/` 迁移到服务器（依赖和 `.next/` 不必迁移）。`data/` 包含私人文件和账号，不提交到 Git。
2. 创建 `.env`：

```dotenv
SITE_DOMAIN=你的域名
HOST_DATA_DIR=./data
IRIS_BASE_URL=http://host.docker.internal:8000
IRIS_API_TOKEN=
```

3. 确认 `data/` 可被容器中的 node 用户读写。官方 node 镜像的用户 UID 为 1000；例如服务器上使用 `sudo chown -R 1000:1000 data`。
4. 执行 `docker compose pull caddy`，再执行 `docker compose up -d --build`，用 HTTPS 域名访问。数据库和文件持久化在服务器 `HOST_DATA_DIR` 指定的目录，默认 `./data/`。

Docker 启动前会只读检查 HTTPS `APP_URL` 和已初始化的站主账号，检查失败则拒绝启动。Compose 设置 `DISABLE_WEB_SETUP=1`，公开环境关闭网页初始化；重设密码仍使用本地命令。登录按可信客户端地址限制 10 次失败 / 15 分钟，另限制 30 次请求 / 分钟；应用 3000 端口只在容器内部开放。`TRUST_PROXY=1` 只适用于这里的受控 Caddy 入口，切勿把同配置的应用直接暴露公网。

HTML 使用每次请求生成的 nonce CSP，附件保持独立 sandbox；Caddy 提供 HTTPS、HSTS 和 22 MB 请求上限。若以后添加 Cloudflare 等前置代理，需要先按其官方地址范围配置真实客户端 IP 和源站限制，不能直接信任客户端传入的转发头。

Iris 在同台服务器上运行时，需允许来自 Docker 网桥的连接，并通过防火墙限制 8000 端口；不要将其直接公开到互联网。使用 Compose 服务运行 Iris 时，可以把 `IRIS_BASE_URL` 改成相应内网地址。Iris 如果仍在家中电脑，需要服务器与电脑之间的私有网络，且电脑必须开机。部署 IIS/Windows 桌面工具等本地能力之前，需要另行检查其云端兼容性。

SQLite 适用于这个单站主、单实例项目。不要给多个应用实例共享同一数据目录。站点通过后端检查权限，文件不放在 public 目录中。

## 备份与恢复

登录后打开“布置小屋”，页面底部的“备份中心”可生成完整备份，显示最近备份时间、内容数量和大小，并下载已有备份。生成期间，正在进行的保存与上传先完成，后续 API 操作短暂等待，保证数据库和附件对应；失败会自动恢复正常操作，不留下可下载的半成品。

网页备份是 `.tar.gz`，包含 `world.sqlite`、全部已登记照片、视频与文档、`backup.json` 和 `RESTORE.md`。保存在 `DATA_DIR/backups/`，沿用 Docker 数据目录的写入权限和持久化挂载；历史备份不参与新包打包，不会递归增长。备份下载仅站主可访问，包含私密内容、账号及会话，请自己保管，并另外下载一份到电脑。

恢复网页备份时停止服务，将压缩包解压到新目录，将 `DATA_DIR`（Docker 使用宿主机 `HOST_DATA_DIR`）指向该目录后重启，再检查原账号、照片与内容。不要覆盖运行中的原目录；详细步骤随压缩包提供。下面的命令行方式仍可使用。

为保证数据库和附件属于同一时刻，备份期间先停止网站写入：本地退出 `npm run dev`，云端运行 `docker compose stop web`。在有 Node 环境的项目目录执行：

```powershell
npm run backup -- D:\MyBlog-backups\2026-10-01
```

备份路径必须位于数据目录外，且目标目录尚不存在；脚本会创建父目录。不带路径执行 `npm run backup` 时保存到 `backups/` 下的新时间戳目录。脚本使用 SQLite 在线备份 API 输出一致的数据库，再复制附件；账号和密码哈希也在备份里。云端使用宿主机 Node 执行备份时，在 `.env.local` 将 `DATA_DIR` 设为 Compose 的 `HOST_DATA_DIR` 对应绝对路径，确保备份同一份数据。

恢复时停止网站，将备份中的 `world.sqlite` 和 `files/` 放入一个新的数据目录。不要把新的数据库覆盖到仍有旧 `world.sqlite-wal` / `world.sqlite-shm` 的目录。

- 本地：在 `.env.local` 将 `DATA_DIR` 设为新目录，重启网站。
- Docker 云端：在 Compose 的 `.env` 将 `HOST_DATA_DIR` 设为新目录的绝对路径，执行 `sudo chown -R 1000:1000 /新目录`，再执行 `docker compose up -d web`，让容器按新挂载重建。容器内的 `DATA_DIR` 保持 `/app/data`。同时更新宿主机备份用的 `.env.local` 中 `DATA_DIR`。

重新启动后确认可登录、资料完整，再恢复正常使用。先保留原目录，以便发现问题时切回。

可以用服务器定时任务在停止写入的维护窗口执行备份，将副本放到另一台设备或私有对象存储。本项目没有自动创建云账号或上传私人资料。
