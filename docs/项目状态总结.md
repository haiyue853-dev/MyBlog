- 名牌只做配色变化，不做位移：它的胶囊填充与高光由顶栏那层静止背景提供，位移会让着色脱离胶囊边、底部露出缝隙；导航和工具是容器内的小胶囊，仍然保留悬停浮起。
- 顶栏使用单层半透明磨砂背景，避免连接时切换多个背景层导致亮度变化；文字保持原位。

- 鼠标移动产生少量音符，自动漂浮淡出，不拦截点击。
- 花朵按钮统一控制动效并记住浏览器选择；首次访问遵循系统减少动画偏好，主动开启后优先采用网站选择。

### 1.3 数据、权限与部署准备

- SQLite 保存条目、附件信息、个人设置、站主账号、会话与登录失败计数。
- 附件原件保存在服务端私有目录，通过后端校验权限后下载，不放入 `public/`。
- 单站主密码登录。首次建站走页面表单；命令行 `npm run setup-owner` 用于修改昵称与重设密码，重设会撤销已有会话。
- 密码使用 scrypt 哈希；会话 Cookie 设置 HttpOnly、SameSite=Lax，HTTPS 下设置 Secure；数据库保存会话令牌的哈希。
- **会话寿命 180 天并自动续期**：在 API 出口统一处理，只在剩余寿命掉到一半以下才写库并重发 Cookie；登出后会话已删除，不会被续期逻辑复活。
- **写操作校验同源**：配置了 `APP_URL` 就以它为准；未配置时按客户端**实际请求的 Host**（`x-forwarded-host` 优先）判断。不能拿 `request.url` 判断，Next 的 standalone server 会把它的 host 写成 `localhost`。
- 登录失败有次数限制，Iris 代理使用接口白名单。
- 提供 Dockerfile、Docker Compose、Caddy 配置，以及数据库和附件备份、恢复说明。
- 私人数据、环境变量、构建结果和测试数据已加入 Git 忽略配置。

网站采用 Next.js 同一个应用承载前端和服务端 API，没有额外独立后端项目。页面通过 `?view=life|collection|files|iris|settings` 切换视图。

数据链路：

```text
浏览器 → Next.js 页面/同源 API → 权限校验 → SQLite + 私有附件目录
                              └→ Iris HTTP API → Iris 自己的会话与知识库
```

资料柜原件和 Iris 索引是两套独立数据。导入需要主动选择文件与知识库；删除资料柜文件不会删除已经导入的 Iris 副本。

### 主要 API

| 路径 | 用途 |
| --- | --- |
| `GET /api/auth` | 登录状态与站主是否已初始化 |
| `POST /api/auth/login`、`logout` | 登录与登出 |
| `POST /api/auth/setup` | 首次建站（仅在还没有站主时可用，之后永久 409） |
| `/api/items`、`/api/items/:id` | 生活/收藏列表、详情、增改删 |
| `/api/files`、`/api/files/:id` | 文件列表、上传、下载和删除 |
| `GET/PUT /api/profile` | 个人资料读取与保存 |
| `/api/iris/*` | 受保护的 Iris 白名单代理 |
| `POST /api/iris/import` | 把资料柜文件副本导入 Iris |

### 4.3 已知小问题与当前能力边界

- **两处重复文案尚未定夺**：页脚的「回到小屋顶端 ↑」与右下角浮动 TOP 按钮功能重复；小屋寄语第 3 句「把日常收好，把喜欢留下。」与页脚正文一字不差。

- 最新头部延展已经过内置浏览器检查，用户普通浏览器中的最终视觉效果仍待实际体验确认，尚未做全面跨浏览器验收。

- 会话续期依赖响应头 `Set-Cookie`。曾踩过一个坑：`Response.json()` 的 headers 守卫是 `"response"`，`Set-Cookie` 属于 forbidden response-header name，直接 `append` 会被**静默丢弃**——库里续期成功、单测也能过，但客户端一个字节都收不到。现在已改为重新构造 `Response`，改动这一处时务必直接读响应头验证。
- 文件检索目前是文件名/分类匹配；生活与收藏检索是标题、正文和标签匹配。跨文件内容的语义检索交给 Iris，尚无网站统一全文搜索。
- 当前是单实例、单站主方案；没有多用户协作、嵌套文件夹、多图相册或访客评论功能。这些属于后续可选扩展。

## 5. 下一步建议

### 第一步：填入真实内容并本地试用

站主已经建好，直接刷新浏览器点击右上角锁图标登录，然后在「布置小屋」里设置名称、头像、简介和主题色。建议先保存一条私密生活记录、一条公开收藏和一份个人文件，退出登录检查实际可见范围。花朵按钮开启后，体验头部连接与低密度音符，确认是否还需要视觉微调。

如果预览进程已经不在（例如重启过电脑），再启动它。开发与正式预览二选一运行，避免同时占用 3000 端口：

```powershell
npm run build
npm start
```

### 第二步：决定要不要推送到远端

远端是公开仓库，当前落后 9 个提交。推送前先用 `git grep` 扫一遍硬编码的私人信息与密钥（注意 `package-lock.json` 的 base64 integrity 里可能误命中短词），确认无误后：

```powershell
git push origin main
```

若本机提示选择凭据助手，选 `manager`；`gh` 的登录状态与 git 的凭据是两套独立机制。

### 第三步：完成一次真实 Iris 闭环

启动本地 `D:\agent\Iris-agent`，确认 API 地址，登录网站后：连接状态 → 选择知识库 → 导入一份小型文档 → 观察资料柜的索引进度走到“索引已完成” → 提一个基于文档的问题 → 检查答案与原文下载（文件名应为原文件名）→ 验证停止回答。

实际模型调用可能消耗已配置模型服务的额度。这一步应使用本人愿意导入的资料，保留资料柜原件作为独立副本。本轮只用模拟上游验证了进度与文件名，真实索引耗时与失败文案仍需实测。

### 第四步：确定云部署方式

先确定服务器、域名，以及 Iris 是迁移到同台服务器还是保留在本机。当前代码最直接的部署路径是单台 Linux 服务器运行 Compose：Caddy 提供 HTTPS，Next.js 运行一个实例，SQLite 与附件挂载到宿主机持久化目录。

迁移前初始化站主并备份；设置 `SITE_DOMAIN`、`HOST_DATA_DIR`、`IRIS_BASE_URL` 和可选令牌；**部署时务必配置 `APP_URL` 为真实 HTTPS 域名**（否则 Secure Cookie 需要依赖 `x-forwarded-host` 判断）。完成目录权限配置后启动：

```sh
docker compose up -d --build
```

上线验收应包含 HTTPS、登录、私人资料授权、20 MiB 附件上传、Iris 流式回答、服务重启后的数据保留，以及从备份恢复。

### 第五步：安排备份与后续小优化

- 首次迁移前执行一次备份，按 README 在停止写入的窗口操作，并把副本保存到项目外。
- 上线后安排定时备份和私有异地副本；演练一次恢复，再开始长期存放重要资料。
- 备份用例在 Windows 上派生子进程失败，属于环境问题；如果要在别的机器上跑测试，先确认 `npm test` 能全绿。
- 待定夺：撤掉页脚与浮动按钮重复的返回顶部入口；换掉与页脚重复的那句小屋寄语。
- 根据真实使用体验再决定是否增加多图、相册、嵌套目录、统一搜索，或把导入进度持久化到数据库。

进一步操作说明见 `../README.md`；此前的设计、修复与验证依据见 `superpowers/implementation-ledger.md`。
