# 小屋部署安全实施计划

> 执行方式：当前会话直接实现，逐项验证；不购买服务器、不发布私人数据。

**目标：** 保留现有小屋体验，修复登录拒绝服务与公开初始化窗口，补齐网页和容器的安全防护。

**架构：** 单实例 Next.js + SQLite + Caddy，仅部署小屋，Iris 后续接入。反代覆盖客户端地址头；应用只在显式信任反代时使用该地址。网页 CSP 使用每次请求生成的 nonce。

**约束：** 不修改正式个人数据；测试使用临时数据库；保持头像上传、页面动效、私密文件权限与 180 天会话体验；不增加第三方依赖。

## 1. 登录限流

- [x] 先写回归：一个地址输错 10 次，另一个地址仍能登录；重启保留限制；过期后恢复；伪造普通转发头不起作用。
- [x] 修改 `src/lib/security.ts`、`src/lib/store.ts`、`src/lib/api/auth.ts`：按可信客户端地址记录失败，10 次 / 15 分钟；另外最多 30 次请求 / 分钟，在密码校验前限制。登录正文限制 8 KB。
- [x] `Caddyfile` 覆盖专用客户端地址头，`compose.yaml` 显式启用信任；应用 3000 端口仅内部开放。
- [x] 运行相关 API、存储、安全回归测试。
