# 备份中心

用户选择：登录后下载照片和数据备份。承接已展示的第一版方案，直接在当前工作区实施，保留已有改动，不提交、不发布。

“布置小屋”末尾添加备份中心：生成完整备份、显示最近备份时间和历史备份、下载已有备份。压缩包采用 tar.gz，包含 world.sqlite、全部已登记附件、backup.json 与 RESTORE.md。SQLite 快照包含收藏、人物分组、标签、多图日记、设置、站主账号、统计和点赞。文件和数据库都不进入公开目录。

服务端使用 Node 内置 SQLite backup API、文件流与 gzip，不增加依赖。备份保存在 DATA_DIR/backups，沿用已有数据目录的写入权限和 Docker 持久化挂载。归档只读取数据库及已登记附件，不包含历史备份，不会递归打包。生成时对同一 Store 的 API 请求使用互斥门：已有请求完成后再生成，期间新请求等待，结束或失败后恢复。普通请求继续允许并发。只支持已有单实例 Node 部署。

GET /api/backups 返回备份历史，POST 创建，GET /api/backups/:id 流式下载。全部要求站主登录；POST 另验证同源。下载为 attachment、private/no-store，并注明包含私密资料与账号信息。备份先写临时目录，全部完成后才发布元信息；失败清理临时产物，不修改业务数据。

恢复采用停止服务、解压至新数据目录、调整 DATA_DIR、重启检查的现有流程；不添加网页恢复或删除功能。历史备份不会自动覆盖。

验证：解压真实备份并通过 Store 恢复账号、设置、私密/公开收藏、多图顺序、附件字节；验证登录和同源保护、失败清理、备份与进行中上传/删除互斥，普通请求并发；浏览器实际生成、下载和重开历史，检查手机布局。现有 CLI 备份保持兼容。
