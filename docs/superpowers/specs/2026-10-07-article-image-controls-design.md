# 正文图片预览与大小调整

日期：2026-10-07。状态：用户回复“开始”，已确认交互方案并授权实现。

## 用户目标与当前行为

用户插入正文图片后看到 Markdown 代码，希望直接查看图片并控制显示大小。当前 TextEditor 使用 textarea，右上角“预览”能显示真实排版；插入窗口提供普通宽度和通栏两档，插入后没有图片调整入口。ArticleImage 已有保持比例的显示和点击放大。

## 方案比较

1. 推荐：保留现有文字编辑器，在正文下方增加图片卡片；卡片显示缩略图、说明和调整入口。调整窗口显示实时图片预览及宽度滑块。改动集中，适用于新图片和已有文章。
2. 仅增加更多宽度档位：实现较少，但编辑时仍看到图片代码，插入后调整不方便。
3. 全面替换为富文本编辑器：图片能直接在正文中拖动，但涉及段落、代码块、粘贴及 Markdown 转换，不属于本次必要范围。

## 推荐交互

- 插入图片窗口增加实时尺寸预览，宽度滑块 25%～100%，每次 5%，保留普通宽度和通栏的已有兼容语义。
- 编辑模式下，只要正文包含已附加的图片，就在正文下方显示“正文图片”卡片。每处插图对应一张卡片，可预览大图、调整宽度和说明，不要求手改 Markdown。
- 点击“调整图片”打开同样的预览窗口；确定后只更新对应的一处插图，正文前后文字与同一照片的其他插入位置不受影响。
- 编辑窗口关闭但未确定时不修改正文。调整完成后可通过右上角“预览”核对整篇文章排版。
- 图片保持原始比例，宽度指占正文的比例，不修改上传文件；小屏幕最大宽度不超过正文。
- 已有普通宽度和通栏图片照常显示，不要求迁移旧文章。仅处理当前文章已附加的图片，不载入外部图片或代码块中的示例。
- 仍使用现有站主编辑权限、草稿与确认发布流程，不修改 Iris 源码，不发布或改写正式博客内容。

## 实现边界与验证

复用 TextEditor、ArticleImage 和现有图片弹窗。扩展 article-images 的图片宽度解析和对应位置编辑，RecordBody 支持百分比宽度；新增独立的图片卡片组件，避免扩大 TextEditor 职责。

以回归测试验证旧宽度兼容、新宽度持久化、更新准确位置、代码块与未附加图片不进入控件。隔离浏览器验证上传预览、调整已有插图、取消不修改、手机无溢出以及保存后大小一致。完成后运行全套测试、类型检查与构建，并更新项目状态。
