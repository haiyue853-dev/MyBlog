# Iris 读取公开网页

用户确认开始接入 Iris 既有联网能力，沿用仅站主使用、不修改 Iris 源码、发布前预览的要求。

根因：博客聊天只传 safe/knowledge，写作面板只传 safe；网页工具位于 research 工具组。现有独立运行环境 web_search.enabled=true，目标 GitHub 请求成功，无需改变运行配置或重启 Iris。

方案：普通聊天增加 research 工具组，保留服务端固定工具组，不接受客户端传入 coding/browser/mcp 等能力。research 提供公开搜索、网页抓取、批量提取和生成资料候选，不执行博客发布。网页资料先在普通聊天读取，回答下方通过现有「整理成博客」进入编辑预览；素材写作面板继续限定 safe，避免 Iris 特殊面经收集路由与结构化 JSON/附件读取冲突。

沿用 Iris 网页抓取内网地址与重定向防护。出站读取公开网页不改变 Iris 端口仅监听 localhost，也不开放匿名使用；站主校验和来源校验先于上游请求。没有添加浏览器自动点击、运行命令、外部消息或自动发布权限。

验证：先用模拟上游测试固定工具组和权限，再经博客处理器与真实 Iris/真实模型读取用户已提供的 GitHub 项目，必须出现网页工具调用并收到完成回答；隔离数据库保持 0 条博客内容。

真实验证：普通聊天经博客处理器调用 fetch_page 成功读取 api.github.com 的公开仓库资料（约 1.4 秒），模型返回带来源的中文回答，隔离博客记录仍为 0。GitHub 主站及原始文件地址在当前网络中出现连接超时，不能据此声称 README 已读取；保留失败证据，不改变抓取防护或 Iris 源码。
