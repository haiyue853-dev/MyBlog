# 聊天回答拟定完整博客稿

用户指出原文搬运导致标题使用回答里的过程说明，明确要求标题等字段全部由 Iris 拟定。本轮用二次整理替代本地复制，并沿用已授权的预览、站主确认发布和不修改 Iris 源码要求。

点击回答下方「整理成博客」后选择文章或日常；博客将该条回答作为 sourceReply 发送到现有 prepare 接口。Iris 根据素材重新拟定标题、正文、摘要、分类和标签，去掉对话开场、工具过程、分隔词和追问；保留可用事实和来源，未核实的项目功能不当作已核实事实。文章输出摘要，日常按较短篇幅整理。

服务端对 sourceReply 校验非空、最多 50000 字，且不能混用附件；普通整理要求仍最多 10000 字。聊天二次整理只请求文本模型（空工具组，知识库 false），不重复读取链接，也不允许自动执行写入。Iris 输出沿用现有内容白名单校验与随机稳定候选 ID，只返回 draft 候选。

整理期间显示进度并阻止重复点击，可以停止。成功才替换候选并打开 Editor 排版预览；失败或取消保留原回答、选择窗口和上一份候选，不回退到第一行截取标题。原有标签页暂存、关闭重开、手工修改、配图、草稿与明确发布保持。

验证：模型拟定的标题等字段完整进入预览；不是回答第一行；请求失败与取消不能假装成功；sourceReply 边界、权限、无数据库写入；实际模型与隔离网页验收标题/摘要/分类/标签填充、进度取消、预览后确认发布。
